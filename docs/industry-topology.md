# 台美產業關聯圖

新增「產業關聯」頁籤，第一版提供半導體與 AI 伺服器兩條產業鏈，以及 18 家台股／美股公司的初始環節歸屬。一家公司可屬於多個環節。初始資料只包含產業環節流向，**沒有把環節歸屬轉成公司供應契約**；公司產品、來源及關係可由管理員持續維護。

## 使用方式

- 選擇產業鏈、市場或「僅我的追蹤股」，搜尋代號、名稱或環節。
- 點選環節或公司查看周邊一／兩層產業環節；公司關係模式僅展開已建檔關係。
- 點線條查看關係類型、來源、日期及審核狀態；待確認關係預設隱藏，主動勾選才顯示虛線。
- 公司卡片開啟既有 K 線／MA 工具。手機預設使用公司清單，拓撲需主動展開，可捲動、縮放。
- 新聞讀取目前範圍前 50 家公司的既有近 45 天資料，最多 80 則；不額外抓取新聞、不讀取他人的私人 AI 成果。
- Podcast 比對當前登入者已保存的逐字稿及既有成果，沒有逐字稿時不自動轉錄。
- 「AI 分析可能傳導路徑」開啟既有個人 AI 視窗，需要使用者主動生成，沿用個人模型與費用設定。提示詞附圖與新聞來源，要求區分事實、推論、反證及標題限制；圖中的事件標記只是提及，不是因果或報酬預測。

## 管理頁面

全站及個人功能設定新增：

| 功能鍵 | 控制內容 |
| --- | --- |
| `market_watch.topology` | 整個產業關聯頁籤與資料 API |
| `topology.company_relations` | 公司供應、合作、競爭關係 |
| `topology.pending` | 是否允許使用者檢視待確認關係 |
| `topology.events` | 相關新聞與 Podcast |
| `topology.analysis` | AI 傳導分析入口 |

既有 `markets.tw`／`markets.us` 同時限制拓撲中的公司與關係；`stock_tools.candles` 限制 K 線入口。個人覆寫沿用既有管理規則。

「產業關聯資料管理」可新增、修改、停用及移除產業鏈、環節、公司歸屬、關係；修改在草稿中，按儲存後發布。產業節點與公司之間透過公司 nodes 欄位建立多重歸屬；公司關係端點使用 `company:2330` 或 `company:US:NVDA`，與產業環節 ID 分開。

新增公司先填股票代號、名稱、所屬環節 ID 與 HTTPS 公司來源。新增關係選起終點、類型、說明、證據來源、日期，經人工核對後改為已審核。來源連結不代表已核實契約，管理員應核對原始揭露。

刪除草稿中的鏈／環節會同步移除相依關係與沒有任何歸屬的公司。資料檢查拒絕重複 ID、失效端點、不合法日期或來源。儲存有明確提示，使用 revision 防止多人互相覆蓋；版本衝突會保留草稿並提示重新載入。

## 後端與部署

- `GET /industry-topology`：有效功能設定與市場篩選後的公開拓撲。
- `GET /industry-topology/news?codes=2330,US:NVDA`：限定公開公司、最多 50 家的既有新聞。
- `GET /management/topology`：獨立管理者登入後取得完整資料與版本。
- `PUT /management/topology`：獨立管理者登入後以 `{revision,document}` 原子儲存，版本衝突回 409。

D1 `industry_topology` 表首次請求自動建立，未儲存時使用程式內初始資料，第一次儲存版本為 1。不需要新增 Secret 或手動 migration。公開資料使用 no-store，前端在重新進入頁籤且快取超過 30 秒時更新，也可按更新資料立即讀取。資料 API 的關閉及市場／子功能限制在後端執行，管理接口持續要求獨立管理者 Session。

部署需同時更新前端與現有 Cloudflare Pages API（或 Worker）；`worker/worker-bundle.js` 隨本次更新。API 尚未更新時前端顯示載入錯誤與重試，不會以示範資料冒充正式設定。

## 範圍

這一版是管理員維護的產業骨架和關係資料庫，未啟用全市場自動擷取、AI 自動審核或付費 GICS／供應鏈資料。增加產業可直接使用管理頁面；新增關係仍需提供依據。以 DOM 與 SQLite 測試驗證互動、權限、版本衝突及資料篩選，尚需實際部署環境的瀏覽器驗收。
